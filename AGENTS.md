# AGENTS.md

Инструкция для ИИ-агентов (Claude Code, Codex, Cursor и других), которые дорабатывают этот репозиторий.
Людям лучше начать с [README.md](README.md) и [docs/GUIDE.md](docs/GUIDE.md).

## Что это за проект

Неофициальная 3D-модель кампуса School 21 в Ташкенте (ул. Зиёлилар, 13) в масштабе 1:1: экстерьер, пять уровней с интерьерами, люди, прогулка от первого лица и праздничный режим. Прод: https://school21-tashkent.vercel.app.

- **Статический сайт без сборки.** `index.html` и ES-модули в `src/`. three.js 0.170 и three-mesh-bvh 0.8.3 подключены через importmap с jsDelivr. Бандлер, TypeScript и npm-зависимости в рантайме не добавляй: проект должен открываться любым статическим сервером.
- **Всё процедурное.** Геометрия строится кодом из данных, а текстуры, картины и экраны рисуются на canvas при загрузке. Бинарные ассеты есть только у людей: `assets/people/*.glb`, модели Quaternius под CC0.
- **Язык.** Интерфейс, комментарии в коде и сообщения коммитов на русском, идентификаторы на английском.

## Запуск

```bash
python3 -m http.server 5321      # из корня репозитория → http://localhost:5321
```

Порт 5321 стоит по умолчанию во всех скриптах `tools/`, другой адрес задаётся переменной `URL=…`.

| URL-параметр | Что делает |
|---|---|
| `?q=high` / `?q=low` | Качество. high: MSAA ×4, GTAO, тени 4096, все 9 моделей людей. low: FXAA, тени 2048, упрощённая мебель, 4 модели. Без параметра телефоны и маленькие экраны получают low |
| `?party` или `#party` | Сразу включить режим «Праздник» |
| `?people=0` | Без людей: быстрее загрузка. Тесты так и запускаются |
| `?crowd=2` | Плотность людей ×2 (от 0,2 до 4). Нужна для съёмки видео, в обычном просмотре дорого |

### Отладочный API в консоли: `window.__s21`

| Поле | Что это |
|---|---|
| `scene`, `camera`, `controls`, `renderer`, `composer` | Объекты three.js |
| `state` | Состояние интерфейса: вид, разрез, время, режимы |
| `world` | `site`, `shell`, `interior` (`levels`, `pick`, `seats`), `overlay` |
| `applyCut('L2' \| null)` | Разрез по уровню (B1, L1, M, L2, L3) |
| `applyTime('day' \| 'eve' \| 'dusk' \| 'night')` | Время суток. `dusk` (синий час) есть только в API, кнопки для него нет |
| `fitCamera(id, instant)` | Ракурс из `PRESETS` |
| `setParty(bool)`, `partyApi()` | Режим «Праздник» |
| `peopleApi()` | Люди: `count`, `mode`, `setMode('normal' \| 'party')`, `people()` |
| `walk` | API прогулки для тестов: `start`, `teleport(u, v, level)`, `lookAt(u, v)`, `setInput`, `step`, `state`, `ground`, `fits`, `inside`, `blockers`, `rebuild` |
| `capture(dt, fwRate)` | Отрисовать кадр с заданным шагом времени. Для покадровой съёмки видео |

## Координаты

Это главное, что нужно держать в голове:

- **Всё в метрах.** `u` идёт вдоль главного (юго-восточного) фасада: 0 — южный угол, 55,2 — восточный, где вход. `v` идёт вглубь здания: 0 — главный фасад, 55,2 — задний. `z` отсчитывается от чистого пола 1 этажа, тротуар у входа на −1,5.
- **Сцена three.js:** `X = u − 27,6`, `Y = z + 1,5`, `Z = 27,6 − v`. Формулу руками не пиши, бери `sx/sy/sz` и `P(u, v, z)` из `src/lib/geom.js`.
- **Уровни (`LEVELS`):** B1 −4,5 (дно атриума), L1 0, M +2,25 (парящая площадка), L2 +4,5, L3 +9,0. Подиум лаунжа на L3 выше пола на 0,6. Верх кровли 13,2.
- **Сетка колонн** 6 × 6 м, оси 0,6 + 6k по u и по v (`GRID`).
- **Ориентиры для проверки:**

  | Ориентир | Координаты |
  |---|---|
  | Турникеты | (45,4; 20,0) |
  | Лифты | (39,8; 21,5) |
  | Статуя на площадке M | (13,75; 26,3) |
  | Экран лектория B1 | (15,4; 21,9) |
  | Ивент-холл (конференц-зал) L1 | u 12,6–30,8, v 0,6–15,9 |
  | Кластер Tashkent L2 | u 0,6–24,6, v 42,6–54,6 |

## Как собирается сцена

1. `build()` в `main.js` ждёт шрифты (до 2,5 с), затем строит `buildSite`, `buildShell` и `buildInteriors()`: на каждый уровень группа `level-<id>`, внутри `Batch` статики, инстансы мебели, светильники и потолок. Потом идут оверлей достоверности, время суток, разрез и камера. В конце асинхронно вызывается `loadPeople()`.
2. «Праздник» строится лениво при первом `setParty(true)`, дальше только переключается `visible`. Люди переставляются: `people.setMode('party')`.
3. Прогулка (`createWalk`) при старте собирает BVH-коллайдер из всего, что лежит в сцене. После правки геометрии нужен `walk.invalidate()`, его уже вызывает `buildInteriors()`.
4. Разрез (`applyCut`) прячет уровни выше выбранного и потолки. Люди и праздник висят в тех же группах уровней и прячутся вместе с ними.
5. Детализация: снаружи издалека прячутся инстансы мебели (`userData.detail`) и люди (`people.setDetail`).

## Частые задачи: куда идти

- **Сдвинуть стену, дверь или зону:** `building.js` (`WALLS`, `DOORS`, `ZONES`). Потом прогулка и `nav-check`.
- **Новая зона:** `Z(level, id, type, name, [u0, v0, u1, v1], { confidence, note })` в `ZONES`. Мебель выбирается по `type` в `zoneContents()` (`interior.js`). Новый тип — новая ветка `case` и функция наполнения.
- **Новый предмет мебели:** функция `xxxGeo()` в `furniture.js`. В функции зоны: `I('key', F.xxxGeo, 'matKey').push(mtx(u, v, z, rotY), color)`. Это один `InstancedMesh` на тип на уровень.
- **Новая картинка, экран или вывеска:** функция в `art.js` или `textures.js`, рисует canvas и возвращает `CanvasTexture`.
- **Персонажи:** `ROLES`, палитры и функции `populateNormal` / `populateParty` в `people.js`. Места у столов, в зале и в амфитеатре приходят из `SEATS` в `interior.js`.
- **Праздник:** `party.js`. Слайды на экранах — `birthdayScreen()` в `art.js`.
- **Время суток:** `TIMES` в `main.js`. Ракурсы: `PRESETS` там же.

Подробные рецепты с примерами — в [docs/GUIDE.md](docs/GUIDE.md).

## Правила и подводные камни

1. **Планировка живёт в `building.js`.** Если build-коду нужна координата комнаты, выводи её из данных (зона, стена, ядро), а не вписывай число. Правишь элемент по новому источнику — обнови его `confidence` (`plan`, `photo`, `video`, `inferred`) и `note`.
2. **Проходимость.** Капсула игрока: радиус 0,28 м, высота 1,75 м, шаг 0,32 м (`PLAYER` в `walk.js`). Нормы:
   - проёмы и проходы между рядами столов — не меньше 0,8 м;
   - поперечные проходы — не меньше 1 м;
   - подступенок — не выше 0,32 м;
   - у краёв площадок, рядов и маршей без перил — ограждение, иначе `nav-check` найдёт обрыв.
3. **Коллизии.** Всё, что лежит в сцене, считается препятствием, кроме исключений `collision.js`. Декор, который не должен мешать ходить (праздник, люди, свет), помечай `userData.noCollide = true`. Мелочь вроде стульев, мониторов и растений пропускается по имени инстанса (`SKIP_INST`). Тяжёлые инстансы сталкиваются по габаритной коробке.
4. **Производительность — главный бюджет.**
   - Статику сливай в `Batch`, повторяющееся — в `Instancer`.
   - Материал на объект не создавай, бери `mats.get(key)`.
   - Каждый человек — один draw call. Толпу меняй коэффициентами, а не циклами по сотням мест.
   - Ориентир `tools/perf.mjs` (headless, q=high, 1440×900, Mac на Apple Silicon): кластер ≈ 36 fps, лобби ≈ 37, снаружи ≈ 51, ивент-холл в «Празднике» ≈ 22. Просадка больше 15 % — повод разобраться до коммита.
5. **Шрифты.** Текстуры с текстом рисуются после загрузки Unbounded, Onest и JetBrains Mono с Google Fonts. Новый шрифт добавь в `<link>` в `index.html` и в список ожидания в `build()`.
6. **Камера из кода.** Если ставишь камеру скриптом и смотришь вверх, задай `controls.maxPolarAngle = Math.PI` и малый `minDistance`. Иначе OrbitControls молча поднимет камеру к уровню цели (так сделано в `tools/shot.mjs`).
7. **Без внешних картинок.** Фото из источников — только референс, в репозиторий их не кладём. Логотипы, фото людей и чужие изображения не добавляем, рисуем процедурно.
8. **Телефоны.** Проверяй `?q=low` и узкую ширину около 380 px. Интерфейс адаптивный, не ломай его.
9. **Стиль кода.** ES-модули, 2 пробела, точки с запятой, одинарные кавычки. Комментарии короткие, по-русски, объясняют «почему».
10. **Дизайн интерфейса.** Без цветных боковых полосок-акцентов (`border-left`) у карточек и панелей.

## Проверка перед коммитом

```bash
cd tools && npm install && cd ..   # один раз: puppeteer-core; нужен установленный Chrome (путь — CHROME=…)
node tools/walk-test.mjs           # 29 маршрутов прогулки по всем этажам → все OK, код выхода 0
node tools/nav-check.mjs           # заливка проходимости → 0 обрывов, 0 закрытых проёмов
node tools/perf.mjs                # кадры/с и draw calls в типовых видах, сравни с ориентирами выше
node tools/shot.mjs /tmp/s "lobby:47.2,25.3,1.65,36.6,25.6,1.25,62"   # посмотреть глазами
```

- Ориентир на сейчас: `walk-test` — 29/29; `nav-check` — 0 обрывов, 0 закрытых проёмов. «Отрезанные участки» в 16 зонах — это нормально: по 1–7 точек в карманах за мебелью и около 70 точек за экраном лектория на B1. Тревожно, если число выросло или отрезалась целая зона.
- `shot.mjs` принимает ракурсы `"имя:u,v,z,цель_u,цель_v,цель_z[,fov][,разрез]"` и `"имя:-"` (кадр как есть). Переменные: `TIME`, `PARTY=1`, `PEOPLE=0`, `CROWD`, `UI=1`, `CLICK=id,…`, `EVAL='…'`, `Q`, `W`, `H`, `JPG=1`. Ошибки консоли страницы печатаются в конце.
- Меняешь вид — сними кадр и посмотри на него. Меняешь планировку или препятствия — прогони `walk-test` и `nav-check`. Меняешь людей, праздник или много геометрии — прогони `perf`.

## Деплой и коммиты

- Vercel, статика без сборки: `vercel deploy --prod --yes` из корня. `.vercelignore` не выкладывает `tools/`, `docs/` и `*.md`.
- `vercel.json` кэширует `/src/*` на 5 минут: после деплоя проверяй с жёстким обновлением страницы.
- Сообщения коммитов на русском. Первая строка — что изменилось для зрителя, например: «Кластеры: проходы 0,8 м, поперечный 1 м». Примеры — в `git log`.
- `tools/node_modules` и черновые скриншоты не коммить. В `docs/screenshots/` лежат только картинки для README.
